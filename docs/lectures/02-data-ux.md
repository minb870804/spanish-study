# 2·3. 데이터와 화면 구조 — 강의 학습

## 원본 (한 곳에서만 고친다)
공부 폴더 `~/Documents/MINB/study/_src/`
- `L{N}_study.html` — 교육자료 (PDF와 웹이 같은 파일)
- `L{N}_bank.json` — 문제은행 100문항. 기존 시험지 28문항(id …-M001~M020, S001~S008)이 그대로 들어 있고 나머지가 추가분
- `style.css` — 교육자료 디자인
- `web/publish.mjs` — "웹에 올려줘" 할 때 Claude가 실행. 위 파일을 Firestore에 올린다

## Firestore (모두 `users/{내 uid}` 아래, 나만 읽고 씀)
| 위치 | 내용 | 누가 쓰나 |
|---|---|---|
| `lectureCourses/{courseId}` | 강좌 제목·부제·순서, 교육자료 CSS | 업로드 도구만 |
| `lectures/{lectureId}` | 목록용: 강의 번호·주제·제목·부제·영상 정보, 장 목록, 셀프 체크 수, 문항 수 | 업로드 도구만 |
| `lectureContent/{lectureId}` | 교육자료 본문 HTML, 문제은행 100문항 (강의를 열 때만 읽음) | 업로드 도구만 |
| `lectureState/{lectureId}` | 문항별 출제 횟수(`seen`), 풀던 시험지(`current`), 셀프 체크(`selfCheck`) | 화면 |
| `lectureAttempts/{자동 id}` | 응시 기록: 강의, 날짜, 객관식·주관식·총점, 틀린 문항과 장 | 화면 |

- 업로드 도구는 관리자 권한(firebase-admin)으로 쓰므로 화면 쪽 규칙은 "읽기만" 허용한다.
- 저장소(GitHub)가 공개라서 강의 내용은 저장소에 넣지 않는다.

## 시험 상태
`없음 → 푸는 중(current.revealed=false) → 채점 중(정답 보기 누름) → 저장됨(기록 생성, current 비움)`
- 정답 보기를 누르는 순간 뽑힌 문항의 `seen`을 1씩 올린다(다음 시험지에서 뒤로 밀림).
- 채점 중에 나가도 current가 남아 다시 들어오면 이어서 채점한다.

## 화면 (한 페이지 `lectures.html`, 주소 뒤 # 으로 이동)
| 주소 | 화면 | 핵심 목표 |
|---|---|---|
| `#/` | 강좌별 강의 목록 | 다음에 볼 강의 고르기. 강의마다 최근 점수·응시 횟수·셀프 체크 |
| `#/L1/study` | 교육자료 | 읽기. 넓은 화면은 왼쪽 장 목차 고정, 좁은 화면은 위쪽 목차 선택 |
| `#/L1/exam` | 시험 | 풀기 → 정답 보기 → 채점 → 저장. 지난 응시 기록도 여기 |

상태별 규칙
- 로그인 전: 로그인 버튼과 "로그인하면 내 강의가 보여요" 안내만.
- 강의 0개: "아직 올린 강의가 없어요. Claude에게 '웹에 올려줘'라고 하세요."
- 불러오기 실패: 다시 시도 버튼, 풀던 답은 기기에도 임시 저장되어 있음.
