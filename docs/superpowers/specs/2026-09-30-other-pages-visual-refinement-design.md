# 나머지 네 페이지 시각 다듬기 — 공용 마감 스타일시트

작성일: 2026-09-30
대상: `study.html`, `diary.html`, `shared-diary.html`, `reading.html`, 그리고 공용 `css/`·`js/app-shell.js`
선행 작업: `docs/superpowers/specs/2026-09-29-home-visual-refinement-design.md` (홈 화면, 2026-09-30 배포 완료)

## 1. 배경

홈 화면을 "조용한 종이 노트" 방향으로 다듬어 배포했다. 사용자가 나머지 네 페이지도 같은 디자인으로 맞춰 달라고 요청했다.

2026-09-30에 네 페이지를 캐시 없는 브라우저로 직접 띄우고 측정했다. 소스만 보면 옛 디자인이 많이 남은 것 같지만 실제 화면은 이미 홈과 가깝다. 인라인 CSS의 그라데이션 대부분은 `css/app-design.css`가 덮어써서 보이지 않는다.

| 페이지 | 줄 수 | 인라인 CSS | 그라데이션(소스) | 이모지(소스) | 명조체 폰트 요청 |
|---|---|---|---|---|---|
| `study.html` | 2,913 | 665줄 | 18 | 92 | 없음 |
| `diary.html` | 910 | 317줄 | 7 | 27 | 없음 |
| `shared-diary.html` | 852 | 209줄 | 2 | 24 | 없음 |
| `reading.html` | 333 | 53줄 | 0 | 0 | 없음 |

화면에서 실제로 보이는 홈과의 차이는 다섯 가지다.

1. 제목·날짜가 명조체가 아니다. Noto Serif KR은 `index.html`에서만 요청한다.
2. 헤더 테마 버튼이 `🌓 테마` / `🌙 다크 모드` 같은 이모지 알약이다. 홈은 44px 아이콘 버튼이다.
3. 카드가 그림자로 구분된다. 홈은 1px 선이다.
4. 장식 이모지가 남아 있다. 스터디 문법 제목의 `📌`, 팁 박스의 `🔊` `🔄`, 히어로 뒤 `🇪🇸` 장식, `✅ 완료` 상태, 빈 상태의 `🌱` `🕊` `💌` `📚`, 사용자 이름 앞 `👤`, 토스트와 힌트 문구 등.
5. 스터디 헤더의 `📚 넥서스 부록` 같은 이모지 링크 버튼.

홈에서 문제였던 "알약 버튼 무더기" 같은 구조 문제는 없다. 스터디의 8칸 탭(홈·학습 계획·단어장·문법·발음·퀴즈·진도 체크·넥서스 연동)은 이미 밑줄 탭이다.

## 2. 사용자가 정한 것

- 방향: 홈과 같은 **조용한 종이 노트**
- 일기장·교환일기의 **기분 이모지**(`MOODS`: 😊😆😌…)는 유지 (홈 작업 때와 같음)
- 일기장의 **감정 태그**(`{ id:'proud', icon:'✨', label:'뿌듯' }` 등)는 **이모지 유지**. 일기를 쓸 때 고르는 내용이지 화면 장식이 아니고, 이미 쓴 일기들도 이 모양으로 기억되어 있다
- 스터디 8칸 탭은 **구조를 그대로 두고** 모양만 맞춘다
- 공유 방식: **공용 마감 스타일시트를 새로 만들어 모든 페이지 맨 끝에 건다** (§4)

## 4. 구조 — 공용 마감 스타일시트 `css/paper.css`

### 왜 새 파일인가

홈 작업에서 확인한 사실이 두 가지다.

- `css/app.css`는 `index.html`만 로드한다. 다른 페이지에 닿지 않는다.
- `css/app-design.css`는 모든 페이지에서 **마지막**에 로드되고, 선택자를 `:is(body,body.dark) …`로 써서 명시도를 올려 두었다. 그래서 그보다 앞에 로드되는 파일(`ui.css`, `app.css`)에 규칙을 추가하면 명시도 싸움이 붙는다. 홈에서는 `:root :is(body, body.dark) …` 같은 올림이 필요했고, 규칙 하나를 지웠더니 스터디 페이지에 회귀가 났다.

`css/paper.css`를 **다섯 페이지 모두에서 `app-design.css` 바로 뒤, 맨 마지막에** 로드한다.

로드 순서는 **명시도가 같을 때만** 승부를 가른다. `app-design.css`의 `:is(body,body.dark) .logo-text h1`은 (0,2,2)이므로, 뒤에 오는 평범한 `.logo-text h1`(0,1,1)은 여전히 진다.

접두사만 맞춰서도 안 된다. `:is()`는 목록 안에서 **가장 높은** 명시도를 따른다. 예를 들어 `app-design.css`의 히어로 규칙 `:is(body,body.dark) :is(.hero h2,.streak-banner .big)`은 `.streak-banner .big`(0,2,0) 때문에 전체가 (0,3,1)이 된다. `:is(body,body.dark) .hero h2`(0,2,2)로는 이기지 못한다.

그래서 원칙은 이렇다. **`paper.css`는 덮어쓸 `app-design.css` 규칙의 선택자를 그대로 복사해 쓴다.** 선택자가 같으면 명시도가 정확히 같고, 뒤에 로드되므로 이긴다. 명시도를 그보다 높이는 것(홈의 `:root :is(body, body.dark) …` 같은 올림)은 `paper.css`에서 금지한다. 덮어쓸 대상이 `app-design.css`에 없는 규칙은 `:is(body,body.dark) …` 접두사로 쓴다. 어떤 방법으로도 이기지 못하면 명시도를 올리지 말고 원인 규칙을 찾아 보고한다.

적용 여부는 **브라우저에서 computed 값으로 확인한다.** CSS를 읽고 "이길 것"이라고 판단하지 않는다. 홈 작업에서 이 판단이 네 번 틀렸다.

### 무엇이 들어가나

모든 페이지에 똑같이 적용할 규칙만 둔다.

- 명조체 제목: `var(--ui-serif)`, 굵기 400. **홈과 같은 기준으로 페이지 단위 제목에만** 쓴다 — 로고(`.logo-text h1`, `reading.html`의 `.brand > span`), 페이지 히어로 제목(`.hero h2`), 페이지 날짜. **카드 제목(`.card-title`)과 본문은 Noto Sans KR 그대로** 둔다. 홈도 "선택한 날의 일정" 같은 카드 제목은 고딕이다. 명조체를 모든 제목에 퍼뜨리면 조용한 인상 대신 산만해진다
- 카드: 그림자 없음, `1px solid var(--ui-border)`, hover에도 그림자 없음
- 헤더 아이콘 버튼 `.icon-btn`: 44×44px, 테두리, 카드 배경
- 작은 라벨 `.ui-eyebrow`

토큰 `--ui-serif`는 이미 `css/ui.css`에 있다(`'Noto Serif KR','AppleMyungjo',serif`). 새 토큰 체계를 만들지 않는다.

### 홈 규칙의 이관

지금 `css/app.css` 1149·1239·1244·1245·1248행 부근에 있는 위 규칙들(명조체 제목, 선 카드, `.icon-btn`, eyebrow)을 `paper.css`로 옮기고 `app.css`에서 지운다. 홈 전용 선택자(`#homeView .hero h2`, `.today-card …`, `#dmDate`, `.calendar-heading > span`)는 `paper.css`에 그대로 두어도 다른 페이지에서는 매치되지 않는다.

**이관의 완료 기준:** 홈의 computed 스냅샷(`tests/fixtures/home-computed-baseline.json`의 `computed` 섹션)이 이관 전후 **바이트 단위로 같아야 한다.** 규칙이 `ui.css` 앞에서 `app-design.css` 뒤로 옮겨가며 캐스케이드 위치가 바뀌므로, 모습이 그대로임을 반드시 증명한다. 달라지면 이관이 아니다.

`ui.css`에 들어간 크로스페이지 hover 규칙(`:is(.card,.section-card,.reading-card):hover { box-shadow:var(--ui-shadow) }`, Task 8b)은 `paper.css`의 "hover에도 그림자 없음"과 목적이 겹친다. `paper.css`가 뒤에서 이기므로 이관 후 중복이 되면 지운다. 지울 때 `tests/cross-page.cjs`가 계속 통과해야 한다.

### 폰트

`study.html`, `diary.html`, `shared-diary.html`, `reading.html`의 Google Fonts 링크에 `family=Noto+Serif+KR:wght@400`을 더한다. 400만 요청한다. 홈에서 600을 뺐던 이유와 같다 — 렌더 블로킹 CSS가 커지는데 쓰지 않는다.

## 5. 테마 아이콘 공용화

테마 버튼을 그리는 코드가 지금 세 벌이다.

| 페이지 | 버튼 | 그리는 곳 | 현재 출력 |
|---|---|---|---|
| `index.html` | `#themeToggle.hbtn.icon-btn` | 인라인 `updateThemeButton()` | 달/해 선 아이콘 |
| `diary.html`, `shared-diary.html` | `#themeToggle.hbtn` | `js/diary-common.js:42` | `🌙 다크` / `☀️ 라이트` |
| `study.html` | `#themeToggle.theme-toggle-btn` | 인라인 `updateThemeButton()` (2676행 부근) | `🌙 다크 모드` / `☀️ 라이트 모드` |

이모지만 바꾸면 세 곳이 다시 어긋난다. 모든 페이지가 이미 로드하는 `js/app-shell.js`에 아이콘 그리기를 한 곳으로 모은다.

- `app-shell.js`가 `#themeToggle`에 달/해 선 아이콘과 `aria-label="테마 바꾸기"`를 그리는 공용 함수를 제공한다
- 세 곳의 기존 그리기 코드는 그 함수를 부르도록 바꾼다. **함수 이름 `updateThemeButton`, `toggleTheme`은 유지한다** (페이지의 다른 코드와 `onclick`이 부른다)
- `app-shell.js`는 `defer`로 로드되고 `index.html`의 인라인 스크립트는 그보다 먼저 실행된다. **스크립트 실행 순서와 무관하게** 최종적으로 아이콘이 그려져야 한다. 페이지 코드가 먼저 이모지를 쓰고 `app-shell.js`가 나중에 덮든, 그 반대든 결과가 같아야 한다
- 버튼에 `.icon-btn` 클래스를 붙여 크기와 모양을 `paper.css`에서 받는다

## 6. 페이지별 변경

**공통 (네 페이지)**

- 헤더에 숨겨진 중복 링크(`🏠 Minb`, `💌 교환일기`, `🇪🇸 스터디`, `📔 내 일기장`)의 이모지 제거. `app-design.css`가 `.header-right > a.hbtn`을 숨기지만 화면 낭독기와 소스에는 남아 있다
- 토스트·힌트 문구의 장식 이모지 제거. 홈에서 만든 정적 검사(`findMessageSinks`)를 이 페이지들에도 적용한다
- 빈 상태 문구의 장식 이모지 제거 (`🌱`, `🕊`, `💌`, `📚`)

**`study.html`**
- 헤더의 `📚 넥서스 부록` 링크 → 글자만. 외부 링크임은 유지
- 문법 섹션 제목의 `📌` 제거
- 팁 박스의 `🔊` `🔄` → 선 아이콘. 박스 왼쪽 표지가 이것뿐이라 지우면 구분이 사라진다
- 히어로 뒤 `.hero::after { content: '🇪🇸' }` 장식 제거

**`diary.html`, `shared-diary.html`**

- 임시 저장 힌트 `📝 임시 저장본 복원됨` → 글자만
- `MOODS`, 감정 태그, 일기 목록의 기분 표시(`${e.mood || '📝'}`)는 유지. 목록의 `📝`는 기분을 고르지 않은 일기의 자리표시라 기분 칸의 일부다

**`reading.html`**
- 이모지 없음. 명조체와 선 카드만 `paper.css`로 받는다. `.brand > span` 로고도 명조체로

## 7. 테스트 전략

홈에서 효과가 확인된 방식을 네 페이지로 넓힌다.

1. **현재 모습 고정 (변경 전):** 네 페이지 각각을 375·1280에서 전 요소 computed 스냅샷으로 떠서 픽스처로 둔다. `tests/home-visual.cjs`의 스냅샷 방식과 `tests/recurrence.cjs`의 `fixture(…, {page})`를 재사용한다. 규칙 수·`cssHash`도 함께 고정한다.
2. **`paper.css` 신설과 홈 규칙 이관:** 홈 스냅샷의 `computed` 섹션이 바이트 단위로 같아야 한다. 네 페이지는 이 단계에서 바뀌는 게 정상이다(명조체·선 카드 적용). 바뀐 요소가 전부 제목·카드·헤더 버튼인지 확인한 뒤 기준을 갱신한다.
3. **페이지별 변경:** 페이지마다 바뀐 computed 차이가 그 페이지의 의도한 변경인지 확인하고 기준을 갱신한다. 홈에서 두 번 겪은 "스냅샷이 못 보는 곳"(일정 행이 없는 픽스처, `:hover`, 동적 문자열)은 행동 테스트로 따로 단언한다.
4. **이모지 스윕:** 홈의 렌더 스윕과 정적 검사를 네 페이지에 적용한다. 허용 목록은 `MOODS`, 감정 태그, 기분 자리표시, 학습 내용 중 정보인 것으로 한정한다.
5. **회귀:** `tests/minb-regression.cjs`(36), `tests/cross-page.cjs`, `tests/diary-storage.cjs`가 매 단계 통과해야 한다. 일기·교환일기의 초안·동기화 동작이 여기서 지켜진다.

## 9. 알려진 위험

- **스크립트 실행 순서.** 테마 아이콘이 `defer`와 인라인 스크립트 사이 순서에 따라 이모지로 되돌아갈 수 있다. §5의 "순서와 무관" 요구와 행동 테스트로 막는다.
- **학습 내용과 장식의 경계.** 스터디의 이모지 92개 중 일부는 학습 정보일 수 있다. 판단이 모호하면 지우지 않고 목록으로 남겨 사용자가 정한다.
- **`app-design.css`와의 관계.** `paper.css`가 뒤에서 이기므로 새 규칙은 쉽게 적용되지만, `app-design.css`에 남은 규칙과 효과가 겹치거나 모순될 수 있다. 겹치는 규칙은 이번 작업에서 지우지 않는다. `app-design.css` 정리는 별도 작업이다.
- **이 머신 의존 기준선.** 스냅샷의 폭 값은 macOS 대체 글꼴에 의존한다. 홈과 같은 한계다.

## 10. 확인 방법과 배포

로컬에서 `MINB_ROOT` 복사본으로 테스트를 돌린다(이 네트워크 볼륨은 `page.goto`가 간헐적으로 실패한다). 배포는 홈과 같다: 작업 브랜치 → `main` 병합 커밋 → `origin/main` 푸시 시 Vercel 자동 배포. 이 볼륨에서 `git merge`가 `stash failed`로 실패하면, `main`이 브랜치의 조상임을 확인한 뒤 `git commit-tree`로 같은 병합 커밋을 만든다.

실기기 확인이 필요한 것: 네 페이지의 명조체 표시, 스터디 학습 화면의 가독성, 일기 작성 흐름.
