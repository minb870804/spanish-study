# 홈 화면 시각 다듬기 — 버튼 정리와 종이 노트 타이포그래피

작성일: 2026-09-29
대상: `index.html` (홈 대시보드, 달력, 날짜 팝업) 및 그에 딸린 CSS

## 1. 배경

사용자가 현재 UI를 "전체적으로 촌스럽다 / AI가 만든 것 같다"고 평가했다.

주의: 이 작업을 시작할 때 세운 첫 진단(그라데이션 헤더, 이모지 뱃지 범벅, 카드 안 카드)은 2026-09-10 스크린샷 기준이라 **이미 낡은 것이었다**. 그 사이 `53a46e2 민비앱 화면을 차분한 기록 중심 디자인으로 정리`(2026-09-28)가 들어가 `css/app-design.css`가 생겼고, 그라데이션 헤더·입체 카드·강한 그림자는 이미 제거됐다. 실제로 띄워 확인한 결과 방향은 이미 "차분한 기록 중심"에 가깝다.

현재 상태에서 남은 문제는 셋이다.

1. **홈의 버튼 무더기.** 달력에 닿기 전 알약 버튼 9개를 지난다 — `주간`·`월간`, `월 리포트`·`금주 현황`·`🔍 검색`·`오늘`, `전체`·`내 일정`·`공유 일정`. 좁은 폭에서 세 줄로 접히며 화면 절반을 차지하고, 정작 달력은 스크롤해야 나온다.
2. **날짜 팝업이 개편에서 빠졌다.** 제목의 📅, 기록 버튼 넷의 💪🍺🩸❤️와 원색 테두리, 일정 줄의 `!중요`·`기타`·`🔒나만·공유하기` 뱃지가 그대로다. 홈과 문법이 다르다.
3. **글자와 여백에 위계가 없다.** 전부 같은 산세리프에 굵기만 다르고, 카드마다 둥근 테두리와 연한 그림자가 균일하게 깔려 있다. 흔한 UI 프레임워크 기본값처럼 읽히는 지점이다.

## 2. 현재 구조

`index.html`은 6,659줄이고 인라인 `<style>`이 34~1189줄(1,155줄)이다. 그 뒤로 스타일시트가 순서대로 걸린다.

```
34~1189   인라인 <style>
1191      css/ui.css            토큰(--ui-*)과 공통 프리미티브
1192      css/schedule-editor.css
1193      css/home-settings.css
1195      css/recurrence.css
1196      css/app-design.css    ← 9/28 개편. 앞의 모든 것을 덮어쓴다
```

`app-design.css`는 거의 모든 규칙이 `:is(body,body.dark) ...` 형태다. 이는 인라인 규칙을 이기기 위해 명시도를 올린 것으로, 스타일이 층층이 경쟁하고 있다는 신호다. 같은 속성이 서로 다른 파일 두세 곳에 흩어져 있어 한 곳을 고치면 다른 곳이 튀어나온다. 이번 "촌스러움"의 숨은 원인이자, 다음에 손댈 때 더 엉킬 부분이다.

## 3. 사용자가 고른 것

- 방향: **조용한 종이 노트** (시안 3개 중 선택)
- 이모지: **기록 버튼만 선 아이콘, 나머지 UI 이모지는 제거**
- 홈 레이아웃: **제안대로 버튼 재배치 + 명조체 도입, 단 ‹ › 화살표는 유지**
- 순서: **홈 먼저**, 스터디·일기·교환일기·독서는 다음 차례

`index.html`의 헤더, 홈 대시보드, 달력 카드, 날짜 팝업(`#dayModal`), 그리고 그에 딸린 CSS.

### 제외

- 사용자가 고른 카테고리 아이콘(`cat.icon`), 교환일기 기분 이모지(`MOODS`), 카테고리·소유자 색(`cat.color`, `MEMBER_SIGNATURES`) — 모두 의미를 가진 데이터다
- 일정 수정 창(`js/todo-editor.js`)의 구조. 9/28에 이미 정리됐다. 색·간격만 따라 맞춘다
- 스터디·일기·교환일기·독서 페이지 내부
- 페이지 추가·삭제, 이동 경로 변경

## 5. 변경 내용

### 5.1 헤더

- `🌓 테마` 버튼(1229줄)을 **달/해 선 아이콘**으로 교체. 글자 "테마"는 뺀다
- 달력 도구에 있던 `🔍 검색`(1267줄)을 **헤더로 이동**하고 돋보기 선 아이콘으로 교체
- 로고 "Minb"를 명조체로

### 5.2 홈 달력 카드 — 버튼 재배치

버튼은 하나도 없애지 않는다. 자리만 옮긴다.

| 지금 | 바뀐 자리 |
|---|---|
| `주간` `월간` (1260줄) | 달력 제목 바로 옆 세그먼트로 유지 (레이블을 `주` `월`로 줄임) |
| `🔍 검색` (1267줄) | 헤더 아이콘으로 이동 |
| `전체` `내 일정` `공유 일정` (1279줄~) | 알약에서 **밑줄 탭**으로 |
| `월 리포트`(1265줄) `금주 현황`(1266줄) `오늘`(1268줄) | 달력 **아래 작은 글씨 링크 줄**로 이동 |
| `‹` `›` + `calMonthLabel` (1271~1273줄) | **그대로 유지** (사용자 선택 B) |

`openMonthReport()`, `openSobrietyModal()`, `openSearchModal()`, `goToday()`, `setCalendarView()`, `setScheduleFilter()`, `moveCalMonth()` 핸들러와 `#calPrev` / `#calNext` / `#calMonthLabel` ID는 그대로 둔다.

### 5.3 날짜 팝업

- `#dmDate`의 📅 제거, 명조체 적용
- 기록 버튼 4개(1494~1497줄)의 💪🍺🩸❤️를 **같은 굵기(stroke 1.6)의 선 아이콘**으로 교체하고, 원색 테두리를 중립 테두리로. `aria-pressed` 상태 표시는 배경 톤 차이로 유지한다. 버튼 ID와 `onclick`은 그대로
- `✕ 닫기` → `닫기`
- 일정 줄의 뱃지 3개를 `중요 · 19:30 · 기타 · 나만` 형태의 **작은 회색 한 줄**로. "중요"만 색을 남긴다
- 소유자 색 점은 유지한다 (누구 일정인지 구분하는 정보)

### 5.4 글꼴과 여백

- Google Fonts 링크(29줄)에 **Noto Serif KR 400/600** 추가. 날짜·섹션 제목·로고에만 쓴다. 본문은 Noto Sans KR 유지
- 본문 글꼴이 늦게 와도 글자가 사라지지 않도록 `display=swap`을 유지한다 (현재 링크에 이미 있음)
- 카드의 둥근 테두리와 그림자를 줄이고 **얇은 선 구분**으로 바꾼다
- 섹션 제목을 작은 자간 넓은 라벨로 낮춰 내용이 먼저 읽히게 한다

비용: 웹폰트가 하나 늘어 첫 로딩이 조금 느려진다. 사용자가 이를 알고 선택했다.

### 5.5 달력 날짜 칸

일정 라벨의 원색 바탕을 **왼쪽 가는 색 막대 + 본문색 글씨**로 바꾼다. 카테고리·소유자 색은 막대에 남으므로 구분 기능은 유지된다. 한 줄 자르기(말줄임표 없음)는 사용자가 명시적으로 요청했던 동작이므로 유지한다.

## 6. 작업 방식

### 1단계 — CSS 이전 (보이는 변화 없음)

인라인 `<style>`(34~1189줄)을 `css/app.css`로 옮기고 `<link>`로 건다. **규칙 내용·순서·선택자를 바꾸지 않는다.** 로드 순서(인라인 위치 → `ui.css` → … → `app-design.css`)를 그대로 보존해야 한다. 뒤 파일들이 앞을 덮어쓰는 것에 의존하고 있기 때문이다.

완료 기준: 이전 전후 스크린샷이 동일하다.

### 2단계 — 화면별 변경

고치는 화면마다, 그 화면에 걸린 `app-design.css` 덮어쓰기 규칙을 `app.css`의 원래 규칙에 **합치고** `app-design.css`에서 지운다. 합치면서 `:is(body,body.dark)` 명시도 올리기도 제거한다. 손대지 않는 화면(스터디·일기 등)의 규칙은 `app-design.css`에 그대로 남겨둔다. 그 페이지 차례가 오면 같은 방식으로 흡수한다.

한꺼번에 전부 합치지 않는 이유는, 건드리지 않는 화면까지 위험에 넣지 않기 위해서다. 대신 손댄 화면은 스타일이 한 파일로 모인다.

## 7. 회귀 확인 항목

2026-09-11에 가족 피드백으로 반영한 동작들이다. 개편 후에도 유지돼야 한다.

1. FAB(＋)이 달력에서 고른 날짜로 열리고 시작일·종료일이 그 날짜로 채워진다. 대시보드 "오늘 할 일" 카드의 추가 버튼은 계속 오늘로 연다
2. 일정 수정 창의 삭제 버튼이 만든 사람에게만 보이고, 확인창과 실행 취소가 동작한다
3. 교환일기가 다시 들어올 때 오늘 날짜로 오고, 상대방 일기가 맨 위에 있고, 카드 제목에 상대방 이름이 나온다

**별건으로 확인이 필요한 사항:** 9/11에 요청받은 "세부설정 기본 펼침"이 9/28 개편 후 다시 접혀 있다(`#todoAdvOptions`가 `hidden`). 다만 그때와 구조가 달라져 **날짜·시간은 접힘 밖으로 나와 항상 보이고** 장소·알림·카테고리만 접혀 있다. 원래 불편의 원인(시작일을 매번 펼쳐 고쳐야 함)은 해소된 상태다. 이 스펙에서는 현재 동작을 그대로 두고, 사용자에게 확인 후 별도로 처리한다.
